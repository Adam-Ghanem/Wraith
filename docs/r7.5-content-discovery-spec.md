# R7.5 — Bounded Content Discovery Specification

## Purpose

R7.5 adds a deterministic, project-scoped, wordlist-driven content-discovery command for explicitly authorized web roots. It identifies meaningful accessible resources from a supplied local wordlist and records evidence. A discovered path is an observation, not a vulnerability, validation result, or finding.

## Mandatory boundary

The command requires an explicit project, `--authorized`, an explicit base URL already represented in the selected project's R2 evidence, and an explicit local wordlist. Every non-dry-run request uses the existing R3 `httpengine.Client`; R3 invokes R1 for target, redirect, and resolved destination checks. R7.5 creates no HTTP client, resolver, socket, dialer, browser, subprocess, external API, remote wordlist download, or alternate redirect path.

## Input and target rules

Wordlist input is a bounded local text file. Lines are trimmed, deduplicated, sorted, restricted to relative rooted paths, and rejected when they include a scheme, authority, fragment, query, `..` traversal segment, control character, or excessive length. The normalized list is capped before any request. An explicit operator-supplied base URL is normalized and must correspond to a project-local canonical R2 endpoint or asset; cross-project reuse fails.

GET and HEAD only are permitted. Every run has a request cap, worker cap, rate bound, response-size cap, per-request timeout, total-duration deadline, cancellation propagation, redirect cap, and a bounded result count. The optional recursive mode has a hard depth cap and defaults to depth `0`; it creates only wordlist-derived children below meaningful HTML-like candidates and never parses or follows page links. R3 retains final authority over destination and redirect authorization.

## Discovery semantics

The plan first obtains a single bounded baseline through R3 at a deterministic reserved path. Candidates are then requested through R3. A result is meaningful only when it is an allowed response class and materially differs from the baseline by status, content type, normalized body fingerprint, or bounded body length. A candidate that merely matches a soft-404 baseline is not reported. Results are sorted by canonical URL and carry no raw response body.

## Evidence and persistence

Each meaningful candidate reuses R2 `Endpoint` identity (`GET` plus canonical discovered URL) and appends a project-scoped redacted observation with source `contentdiscovery.r75`. The payload is restricted to normalized path, status, content type, bounded length, response fingerprint, baseline-difference metadata, and redirect count. It excludes response bodies, request values, cookies, authorization material, tokens, and arbitrary headers.

## Explicit exclusions

R7.5 does not use remote or downloaded wordlists, link crawling, sitemap/robots expansion, directory brute force beyond the supplied bounded entries and configured recursive depth, authentication attacks, credential testing, form submission, JavaScript execution, parameter fuzzing, vulnerability claims, severity, confidence, findings, or R8 validation. It stops before R8.
