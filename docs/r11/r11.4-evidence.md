# R11.4 Evidence Chain

R11.4 preserves a project-scoped trace from **R11.3 signal** to **R11.4 candidate and result**, then to **redacted R2/R8 observations**, **R11.4 finding candidate**, and an **R9 correlation identifier**. Every reference is deterministic, bounded, and free of raw payload or credential material.

| Permitted evidence | Prohibited data |
| --- | --- |
| Signal/test/finding fingerprints; endpoint and parameter identities; injection class and signal type; response status; content type; normalized structural fingerprint; bounded error classification; redacted validator/rule/lifecycle/reproducibility metadata; request count and stop reason. | Raw payload values; request bodies; full response bodies; cookies; `Authorization` headers; passwords; tokens; API keys; session secrets; credentials; direct request-template serialization. |

R8's existing validation contract creates `observed` results and reproducibility keys. R11.4 converts only a `validated` internal result into a temporary evidence-backed finding candidate. It never sets an accepted, confirmed, correlated, or resolved final vulnerability state. R9 receives the candidate and evidence references; R10.5 remains responsible for any later orchestration lifecycle or reporting surface.
