# R11.2 — Smart Content and Parameter Discovery

R11.2 adds project-scoped discovery candidates, not a second asset model and not a vulnerability scanner. `internal/smartdiscovery` consumes the R5 inventory—which is already a deterministic R2 projection—and can convert already-local R6 static-report URLs, routes, requests, and non-sensitive parameter references into seeds. No JavaScript, crawler, browser, DNS, or network execution is introduced by planning.

| Mode | Candidate inputs | Network behavior |
| --- | --- | --- |
| Passive | Existing R5/R2 inventory, explicit safe local wordlist, and local R6-derived seeds. | None. |
| Standard/deep planning | Passive inputs plus strictly bounded API-version and safe documentation/configuration heuristics. | None unless `--verify` is also supplied. |
| Explicit verification | Selected URL-like candidates only. | One R10.5-budgeted, rate-limited, concurrency-bounded `HEAD` request per candidate through the caller-supplied R3 client. |

Candidate values are canonicalized through R2 URL handling, fingerprinted project-locally, deduplicated, stable-sorted, and annotated with all independent provenance records. A candidate remains `planned`; a `found`, `not_found`, redirect, or error classification is response metadata—not a security finding. R8 owns validation and R9 owns correlation.

The CLI keeps Phase 1 local discovery intact and adds a positional web form:

```text
wraith discover TARGET --project PROJECT --authorized --dry-run --output json
```

`--dry-run` and the default non-`--verify` mode perform no network work. `--verify` is explicit and supports only non-destructive `HEAD`; R3 owns policy, destination, and redirect handling. Local wordlists must be explicitly supplied and are size/entry/length capped. Secret-like paths and values, including `.env`, `.git`, key, token, password, cookie, and authorization material, are rejected.

## Deliberate limits

The R11.2 branch does not introduce autonomous crawling, form submission, credential attacks, raw body persistence, unrestricted virtual-host/DNS enumeration, backup permutations, validation, findings, or R11.3 injection testing. Candidate persistence and R10.5 phase scheduling remain separate integration work; successful optional verification writes a redacted R2 observation only.
