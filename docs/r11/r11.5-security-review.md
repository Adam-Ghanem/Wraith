# R11.5 Security Review

| Audit area | Result |
| --- | --- |
| Network and process capability | `internal/riskintelligence` imports no HTTP, DNS, socket, transport, process, shell, or resolver implementation. It performs deterministic in-memory and SQLite-local work only. |
| Source integrity | `AssessFinding` requires validated, repeatable R11.4 evidence and a correlation identifier; rejected and inconclusive evidence is refused. |
| Project isolation | Finding persistence, history, suppression, listing, filters, and CLI queries all carry project ID. A suppression first verifies that the same project owns the target fingerprint. |
| Secret minimization | Candidate fingerprints and raw payloads are not copied into security findings. Reference filtering rejects secret-like values, while local CLI output omits finding fingerprints entirely. |
| Risk determinism | The versioned score uses fixed factors and fixed bands. Timestamps are displayed as provenance only and do not change score calculation. |
| Lifecycle safety | Invalid transitions fail closed. Acceptance and suppression require reasons. Expired suppression returns the finding unchanged, and historical events are append-only. |
| R8/R9/R10.5 boundaries | R8 remains validation authority, R9 remains correlation authority, and R10.5 remains lifecycle/report owner. R11.5 has a named R10.5 plan phase but no scheduler or automatic active adapter. |

The remaining integration debt is intentionally explicit: a durable ingestion adapter from R11.4/R9, fuller report rendering, lifecycle metrics persistence, identity-session context binding, analyst-created acceptance/resolution commands, and safe resume semantics require separate approved work. R11.6 and R12 are not started.
