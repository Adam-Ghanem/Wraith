# R11.5 Audit — Security Findings and Risk Intelligence

**Verified base:** `b3096a89ca377185c82f88346c195f9dd2b290d1` on `feature/r11.4-finding-validation`. The `main` branch remains at `42cb8b2` and is not a base for this work.

R11.5 is a local, deterministic risk-intelligence layer. It must consume validated R11.4 finding candidates and R9 correlation outputs, normalize them into project-scoped security findings, calculate explainable risk, apply lifecycle/suppression decisions, and render stable findings/risk views. It must not scan, compose payloads, validate traffic, call R3, create a transport, perform DNS, or replace R8/R9/R10.5 ownership.

| Existing component | Reuse | Boundary retained |
| --- | --- | --- |
| R11.4 `FindingCandidate` and `ValidationResult` | Source only validated, evidence-backed candidate identity, class, confidence, endpoint/parameter IDs, fingerprint, and R9 correlation ID. | Rejected/inconclusive results do not become active findings. R11.5 cannot redo validation. |
| R9 `intelligence.Correlation` | Preserve correlation ID, project scope, and evidence relationships as correlation input. | R9 remains the authority for grouping/deduplication/correlation; R11.5 does not infer a new root cause. |
| R2 `evidence` | Reference existing endpoint/parameter/observation identities rather than copying evidence bodies. | No alternate evidence store and no raw response, payload, credential, cookie, or token persistence. |
| R10 `authsecurity` | Reuse only opaque, project-scoped identity/session context categories when supplied. | No credentials, cookie material, session values, or automatic identity inference. |
| R10.5 `pentest` | Register an explicit risk phase and expose bounded local metrics; reuse report lifecycle ownership. | No scheduler, new network operation, or independent orchestration state. |
| R2/R5 asset intelligence | Accept optional explicit asset/exposure/criticality context, defaulting to `unknown`. | Criticality, exposure, and data sensitivity must never be guessed from host/parameter names. |
| SQLite storage | Add project-scoped, indexed security-finding, history, assessment, and suppression records through one monotonic migration. | Existing observations and older scan-finding tables are not repurposed or rewritten. |

## Current gaps

The repository has early scan-era finding tables and R8/R9 observational/correlation models, but no unified project-scoped security-finding lifecycle, deterministic severity/risk model, risk explanation, suppression/audit trail, or findings/risk CLI. R11.5 therefore needs a dedicated `internal/riskintelligence` domain and a narrow storage adapter. The model must distinguish confidence from severity, preserve R11.4 validation status, and make all status transitions explicit and append-only.

## Proposed data flow

```text
R11.4 validated candidate + R9 correlation
  -> R11.5 normalized SecurityFinding
  -> deterministic classification / severity hint / impact context
  -> versioned RiskAssessment with factors and score band
  -> project-scoped persisted finding + append-only history
  -> stable `wraith findings` and `wraith risk` local output
```

The first implementation increments schema version 12 to 13, validates every project/reference relationship before persistence, uses SHA-256 fingerprints over stable non-secret identifiers, and allows only local data transformations. Suppression, acceptance, resolution, and reopening are explicit project-local lifecycle changes; expiration never silently suppresses a finding.
