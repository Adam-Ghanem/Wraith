# R11.6 Audit — Attack-Surface Graph and Pentest Campaign Intelligence

**Verified base:** `db1592e` on `feature/r11.5-risk-intelligence`. The R11.6 working branch is `feature/r11.6-attack-surface-intelligence`; `main` remains at `42cb8b2` and is not modified.

R11.6 is a deterministic, project-scoped intelligence projection. It consumes existing R2 identities and append-only evidence, R5 inventory classes, R6 static JavaScript references where available, R9 correlation identifiers, R10 authentication categories, R10.5 plan lifecycle, and R11.5 persisted findings/risk. It does not scan, crawl, fuzz, mutate, inject, validate, correlate, authenticate, send HTTP/DNS/socket traffic, or run a subprocess.

| Existing owner | Reused R11.6 input | Boundary retained |
| --- | --- | --- |
| R2 evidence | Project-scoped web assets, endpoints, parameters, observations, stable identities, and redaction state. | R11.6 references identity/evidence IDs; it never alters evidence or stores payloads/bodies/credentials. |
| R5 endpoint intelligence | Bounded inventory, API-like classes, endpoint/parameter attachment, and deterministic ordering. | R11.6 does not derive a crawler or probe path from an inventory item. |
| R6 JavaScript intelligence | Static JS/API/technology relationships only when normalized evidence is supplied. | No JS execution or runtime is added. |
| R9 correlation | Correlation IDs and evidence-backed grouping as finding context. | R11.6 does not deduplicate or assert a new root cause. |
| R10 auth security | Opaque authentication context categories, not secrets or sessions. | No credential, cookie, token, session, or auth-attack data is persisted. |
| R10.5 pentest | Named phase/lifecycle planning and existing global budgets. | R11.6 generates local planned tasks only; it does not create a scheduler, worker, or execution loop. |
| R11.5 risk intelligence | Project-local finding IDs, endpoint/asset references, status, remediation hint, risk score/band/version. | R11.6 cannot validate a finding, alter R11.5 risk, or claim exploitability. |

## Existing graph and required extension

R9 already owns the small `intelligence_graph_nodes`/`intelligence_graph_edges` relationship store and correlation tables. Those tables are intentionally not repurposed because their node kinds and ownership are correlation-focused. R11.6 needs separate `attack_surface_*` tables with a snapshot ledger so a broader graph can be rebuilt reproducibly without changing R9 semantics.

| Required R11.6 model | Identity and edge rule |
| --- | --- |
| Node | `<project> + existing entity identity + R11.6 type`; no random/timestamp identity. Asset, endpoint, parameter, finding, risk, observation, API class, JS/static relationship, and auth context nodes are references where source evidence exists. |
| Edge | `<project> + source + relationship + destination`; deduplicated and created only from evidence, inventory attachment, or R11.5 references. Legitimate cycles are represented, not rejected merely because they are cycles. |
| Snapshot | Deterministic sorted nodes/edges with a timestamp-free graph fingerprint, source version metadata, and bounded counts. |
| Diff | Sorted added/removed/changed node/edge comparison; temporal/regression language remains descriptive and never triggers validation. |
| Campaign plan | A local ordered set of known-entity review/validation-planning tasks, bounded by max tasks/requests/duration/concurrency and marked as non-executing. |

## Data flow and isolation

```text
R2 project evidence + R5 inventory + R11.5 project findings
  -> R11.6 deterministic graph projection
  -> graph snapshot / diff / coverage / visibility gaps
  -> local campaign task recommendations
  -> optional R10.5 planned-phase metadata (never direct execution)
```

Every graph node, edge, snapshot, diff, campaign, and task carries the selected project ID. Rebuild rejects source records from another project, orphan parameters, cross-project finding references, invalid relationship types, duplicate logical identities, unsafe textual metadata, and bounds violations. A project query never accepts arbitrary SQL or unscoped data.

## Scalability and migration plan

R11.6 uses SQLite only and adds one monotonic migration with graph nodes, edges, snapshots, and campaign plans/tasks. Indexes cover project/type/node, source/destination/relationship, snapshot, campaign status, and task priority. Rebuild defaults are deliberately bounded for assets, endpoints, parameters, findings, nodes, edges, paths, and tasks. Graph construction uses maps for deduplication followed by stable sort; fingerprints exclude timestamps. Unbounded traversal, recursive graph execution, distributed queues, PostgreSQL/Redis, graph databases, and automatic campaign execution are rejected alternatives.

## Implementation decision

The first R11.6 increment will provide a pure `internal/attacksurface` model, a narrow storage-native adapter that avoids import cycles, project-scoped rebuild inputs from R2/R11.5, deterministic graph/snapshot/diff/coverage/visibility-gap calculations, local campaign planning, and plan/dry-run CLI output. R10.5 will recognize a named R11.6 phase but will not automatically execute it. R12 remains unstarted.
