# R11.4 Security Review

| Audit area | Result |
| --- | --- |
| Direct HTTP, DNS, sockets, subprocesses | None in `internal/findingvalidation`; active work accepts an injected R3 `httpengine.Client` only. |
| R1 enforcement | A required `PolicyRechecker` is invoked before every baseline and mutation dispatch. Failure stops before transport and fails closed. |
| R10.5 capacity controls | Every dispatched request consumes the shared budget, waits on the global rate limiter, and acquires the shared concurrency controller. |
| Method and payload controls | The runner permits only existing R11.3 `GET`/`HEAD` plans and existing immutable payload registry entries. |
| Instability and cancellation | A `429` terminates the run immediately. Generic 5xx responses are instability, not security confirmation; context errors stop cleanly. |
| Sensitive data | Public candidates and results contain IDs, classifications, and fingerprints only. Payload values are used in memory for R7 reflection analysis and never serialized. |
| Evidence and findings | R8 persists only redacted R2 validation observations. R11.4 cannot create a final finding; its temporary candidate requires validated repeatable evidence, then goes to R9. |
| Project isolation | Candidate construction, run validation, R8 evidence, and R9 handoff all require matching project-local endpoint/parameter identities. |

R10.5 recognizes the explicit `r11.4_validation` phase and the runner emits bounded metrics, but no automatic active phase adapter, durable lifecycle store, resume path, or report adapter is added. Those remain approved follow-on integration work. R11.4 itself does not create a scheduler or modify `main`.
