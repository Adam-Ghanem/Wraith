# R11.4 Finding Validation and Evidence Correlation

R11.4 consumes one project-scoped R11.3 signal and its existing immutable test plan to perform the minimum bounded reproduction. It does not add payload families, scanning, final finding storage, or a correlation engine. The model distinguishes a signal, a validation candidate, a validation result, a finding candidate, and an R9 correlation identifier.

| Stage | Owner | R11.4 behavior |
| --- | --- | --- |
| Signal | R11.3 | Supplies the signal ID, test ID, class, type, confidence, and non-secret fingerprint. |
| Candidate | R11.4 | Enforces project/endpoint/parameter/test identity, profile bounds, stable fingerprinting, and a pending lifecycle state. |
| Reproduction | R11.4 with R1/R3/R10.5 | Rechecks policy before each R3 dispatch; sends only baseline/mutation pairs through shared budget, rate, concurrency, and cancellation controls. |
| Result | R11.4 | Classifies redacted structural differentials as rejected, inconclusive, cancelled, or validated with deterministic repeatability and confidence. |
| Evidence | R2 through R8 | Uses R8 validators and append-only redacted R2 validation observations. |
| Finding candidate | R11.4 | Exists only after a validated result and evidence references; carries a severity hint, not a final severity. |
| Correlation | R9 | Receives only validated, evidence-backed candidates and remains the owner of correlation and deduplication. |

The `safe`, `standard`, and `deep` profiles use one, two, and three baseline/mutation pairs respectively. `GET` and `HEAD` are the only eligible methods. A `429` stops immediately; generic 5xx instability, controlled-request errors, cancellation, and non-repeatable differentials are inconclusive rather than confirmed security findings.

The existing `wraith validate --endpoint` path remains R8's endpoint validator. R11.4 adds planning only through `wraith validate plan TARGET --project PROJECT --authorized --signal SIGNAL`. It prints a bounded no-network plan. Active execution is deliberately library-only because callers must explicitly supply the R1 rechecker, R3 client, R10.5 controls, and R8/R9 adapters.

## Deliberate limits

R11.4 excludes direct HTTP/DNS/socket behavior, direct transport creation, retries, background workers, arbitrary payloads, write methods, credential attacks, secret persistence, raw response-body persistence, final severity, final finding storage, reporting, and any duplicate R9 correlation implementation.
