# R11.1 — Request Mutation Engine

R11.1 provides a deterministic `BuildPlan` API in `internal/requestmutation`. It creates a baseline plus selected candidate variants, without sending any request.

| Mutation location | Supported representation | Safety constraint |
| --- | --- | --- |
| Query | Canonical endpoint URL query component | Query values only; no new endpoint identity. |
| Path | `{parameter}` placeholder in the endpoint URL | Variant fails closed when the placeholder is absent. |
| Form | `application/x-www-form-urlencoded` body | Bounded body and standard URL-form parsing only. |
| JSON | Existing JSON object field or dotted nested field | Valid JSON object, bounded nesting, and bounded body required. |
| Header | One non-sensitive header value | Credential, cookie, token, and API-key headers are rejected. |

The deterministic strategy set covers empty, null, zero, negative, large, short, bounded-long, boolean, URL-encoded, double-URL-encoded, Unicode-boundary, case-variation, and type-variation values. The plan includes an immutable baseline and refuses duplicate fingerprints or a variant count beyond the configured limit.

R11.1 produces no findings, signals, persisted observations, or execution telemetry. Future R11 stages may consume variants only after their own scope review, R1 enforcement, R3-only transport design, budget integration, and explicit approval.
