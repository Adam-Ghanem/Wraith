# R11.6 Attack-Surface Graph and Campaign Intelligence

R11.6 is the final R11 local intelligence layer. It builds a deterministic project-scoped graph from existing R2 assets/endpoints/parameters, R5 inventory classes, and R11.5 finding/risk records. It supports local graph snapshots, differences, bounded coverage and visibility-gap views, and dry-run campaign recommendations. It is not a scanner, crawler, fuzzer, injector, validator, correlator, scheduler, or execution engine.

| Capability | R11.6 behavior | Boundary retained |
| --- | --- | --- |
| Graph identities | Nodes represent known project, asset, endpoint, parameter, finding, risk, observation, API class, and authentication-context references. | Existing R2/R11.5 IDs remain authoritative; no random or timestamp-derived logical identity is introduced. |
| Relationships | Edges cover ownership, exposure, parameter acceptance, finding impact, asset association, risk scoring, supporting evidence, API classification, and recorded authentication context. | Every edge requires known project-local source/destination nodes; R11.6 does not infer unsupported relationships. |
| Snapshots and diff | Stable graph fingerprint excludes timestamps. Snapshot metadata records source version and counts; diffs remain local descriptive comparisons. | No discovery or revalidation is triggered from a change. |
| Coverage and gaps | Counts describe currently known attack-surface coverage and surface visibility gaps such as endpoints without parameters. | Coverage does not claim security, completeness, or vulnerability status. |
| Campaign planning | `campaign plan --dry-run` prioritizes known findings and gaps under bounded task/request/duration/concurrency budgets. | Tasks are recommendations only; R10.5/R1/R3 retain all execution authority. |

## Storage and local CLI

The `014_attack_surface.sql` migration adds project-scoped graph node, edge, and snapshot tables with indexes for deterministic lookup. `wraith surface --project PROJECT` returns a local graph summary, coverage, and visibility gaps. `wraith campaign plan --project PROJECT --dry-run` creates a deterministic local plan only; it never sends a request.

## Deliberate limits

R11.6 has no direct HTTP client, DNS resolver, socket, process/subprocess, JS runtime, distributed queue, autonomous worker, credential/session persistence, attack payload, exploit workflow, active validation loop, or external import. R10.5 recognizes `r11.6_attack_surface` as a plan phase only. **R12 is not started.**
