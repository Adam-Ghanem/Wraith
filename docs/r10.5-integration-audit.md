# R10.5 Integration Audit

## Scope and verified baseline

Audit date: 2026-08-18. Audited branch: `feature/r10.5-pentest-orchestrator`, created from R10 commit `8796152`. `main` remains at `185ee77`; no merge was performed. The repository has R1 policy, R2 evidence, R3 transport, R4 crawler, R5 endpoint intelligence, R6 static JavaScript intelligence, R7 fuzzing, R7.5 content discovery, R8 validation, R9 intelligence, and R10 authenticated-security packages. SQLite migrations currently end at `011_authenticated_security.sql`.

| Existing capability | Reusable integration seam | Verified limitation |
| --- | --- | --- |
| R1/R3 authorization and HTTP safety | `policy.NewGateway`, `httpengine.NewEngine`, `httpengine.Client` | CLI modules create independent engines and limiters. There is no run-wide request, rate, or concurrency budget. |
| R2 evidence | `evidence.Repository` methods are explicitly project-scoped and append observations | Observations have no `run_id`; an additive migration is required for run attribution. |
| R4–R7.5 collection and testing | Package plans/runners accept `context.Context`; CLI adapters already enforce local bounds | CLI commands parse separate flags, reopen SQLite, and contain duplicated engine construction. No common phase interface exists. |
| R8 and R9 | `validation.Run`/`PersistResults`, `intelligence.BuildGraph`/`Correlate` | Validation is endpoint-at-a-time; R9 consumes existing evidence but has no run lifecycle or report model. |
| R10 identities and auth testing | `authsecurity` plans, scheduler, response classification, project-scoped identity storage | Existing sessions are metadata only; no orchestrated authenticated crawl or module-session injection exists. Credential attacks remain dual-gated. |

## Integration gaps and risks

| Required audit topic | Finding and R10.5 response |
| --- | --- |
| Existing interfaces and CLI consistency | `runCrawl`, `runEndpoints`, `runJS`, `runContent`, `runFuzz`, `runValidate`, and `runIntelligence` are private CLI handlers with incompatible option shapes. R10.5 must create an explicit orchestrator contract rather than shelling out or hardcoding their parsing. |
| Duplicate orchestration logic | The active CLIs duplicate database opening, migration, policy evaluator, R3 engine, rate limiter, dry-run, and output rendering. R10.5 must centralize shared lifecycle controls without moving module security logic into one scanner. |
| Unsafe boundaries | Direct module invocation must never replace R1/R3. The orchestrator may create only controlled R3 clients and must not add an HTTP client, DNS resolver, socket, or subprocess route. |
| Cancellation propagation | Individual runners accept contexts, but there is no run-wide cancellation controller, phase graph, or guaranteed aggregation of child status. R10.5 needs one context rooted at the CLI and must pass it to every phase. |
| Global budgets | Existing module limits are local. There is no global request/evidence/finding/duration/concurrency accounting, so independent limits could cumulatively exceed operator intent. |
| Evidence correlation | R2/R9 identities and append-only observations exist, but no `PentestRun` attribution or phase-to-evidence mapping exists. Additive run tables and optional bounded linkage are required. |
| Run lifecycle and reporting | No `PentestRun`, phase state machine, resume validation, event stream, coverage model, or local final report exists. R10.5 must represent partial, skipped, failed, cancelled, and completed phases exactly. |
| Authentication safety | R10 is correctly gated and secret-minimizing. R10.5 must not enable credential attacks from profiles/configuration; it may only schedule them with both explicit flags and remaining global capacity. |

## Approved implementation boundary

R10.5 will be a CLI-first coordinator, not a new scanner. It will use explicit run, phase, budget, and event contracts; consume prior evidence through R2; preserve R8/R9 evidence-only candidate semantics; and record only redacted, project-scoped metadata. The initial implementation must expose deterministic `pentest plan` and zero-network `--dry-run` before live coordination. Resume must reject changed project, target, scope/policy, or incompatible configuration. No R11 work, main merge, SaaS dashboard, unattended scheduling, or invented module capability is authorized.
