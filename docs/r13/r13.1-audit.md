# R13.1 Execution Adapters and Active Assessment Pipeline Audit

**Verified base:** `59b0098` on `feature/r13-active-assessment`. R13.1 work is on `feature/r13.1-execution-adapters`; `origin/main` remains `42cb8b2` and is not modified.

R13.1 connects R13’s scope/task model to existing owner-owned capabilities. It is not a new HTTP engine, crawler, mutation engine, fuzz engine, injection engine, validation engine, finding engine, risk engine, graph, or orchestration database.

| Existing owner | Verified reusable seam | R13.1 adapter rule |
| --- | --- | --- |
| R13 assessment | `assessment.Task`, scope snapshot, `Execute`, deterministic dependency validation, injected `RunTask` callback. | Add an adapter registry/coordinator only; do not add transport or scheduler primitives. |
| R10.5 pentest | Shared `BudgetManager`, `ConcurrencyController`, `GlobalRateLimiter`, phase lifecycle, existing run/phase/event SQLite records. | Reuse the same `RunContext` and lifecycle records. No new assessment tables or independent limiter. |
| R4/R5/R6 | Existing crawl command, R2-backed endpoint inventory, static JS intelligence. | Wrap only public/injected calls; preserve their existing parser, limits, R1/R3 behavior, and R2 identities. |
| R7/R11.3 | Existing bounded fuzz/injection planners/runners with injected R3 and R10.5 controls. | R13.1 task adapters delegate plans/signals to their existing runners; they do not generate new payloads or direct findings. |
| R11.2/R11.1 | Existing deterministic discovery/mutation plan building plus R3-aware verification/mutation composition. | Reuse existing candidates/variants only. |
| R11.4/R9/R11.5/R11.6 | Validation, correlation, findings/risk, and attack-surface ownership. | Adapters can submit to explicit owner interfaces; raw task output cannot become a finding directly. |
| R1/R3 | Existing policy-aware requests and controlled transport. | R13.1 contains no direct client/resolver/dial/TLS/redirect implementation. |

## Current execution paths and compatibility

The existing `pentest` CLI already creates project-scoped run/phase/event records and invokes `pentest.Orchestrator` with a single shared `RunContext`. The existing phase adapter factory only directly wires crawler, endpoint inventory, and intelligence; other phases are explicitly skipped until configuration provides an adapter. This is the compatible insertion point for R13.1: map R13 task types to injected existing-component adapters, then delegate lifecycle persistence to the existing pentest wrapper.

The current R13 `pentest assessment plan` command is no-network and returns an in-memory deterministic plan. R13.1 must preserve that contract and only expose live pipeline execution when an explicit coordinator has received the policy-aware R3 client, R10.5 controls, and owner adapters. It must not infer authorization from discovery or expose secret-bearing authentication data.

## Missing interfaces and deferred work

There is no single pre-existing generic adapter interface joining R4/R5/R7/R11.x, and several active runners require different typed inputs (endpoint identities, R2 templates, injection plans, validation candidates). R13.1 will therefore introduce a minimal task-level interface plus typed adapter constructors. Any stage whose source identifiers cannot be supplied from R2/project state is skipped with an explicit `not_applicable`/`unsupported` reason rather than reconstructed or bypassed.

There is no R13.1-specific SQLite schema requirement: existing R10.5 run/phase/event persistence and R2/R11 owner persistence remain authoritative. New task durability, distributed queueing, background workers, external services, report pipeline changes, authentication changes, and R14 are explicitly deferred.

## Security and test gaps

R13.1 must verify per-task scope expiry, shared budget presence, dependency ordering, cancellation, adapter ownership, and project isolation. Localhost-only fixtures are required for any injected active R3 adapter test. The new code must be audited for direct `http.Client`, DNS, socket, subprocess, secret-bearing durable fields, and new egress paths before release.
