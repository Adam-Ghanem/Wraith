# R13.2 Security Review

## Review scope

This review covers the R13.2 execution package, its small R13.1 registry hardening, and the explicit assessment-run CLI path. It verifies that orchestration stays below the R13 planner but above existing owner components without creating a bypass around R1, R3, R10.5, R2, or R11 lifecycle ownership.

| Security property | R13.2 control | Regression coverage |
| --- | --- | --- |
| Project and scope isolation | Request, task, scope, and active SQLite scope-version matching are required. | Malformed plan, project mismatch, expired scope, and persisted-scope CLI tests. |
| R1 revalidation | An injected evaluator runs before execution, each scheduling cycle, and just before dispatch. | Authorization-denial and pre-dispatch revocation tests prove zero adapter calls. |
| R3 ownership | Execution code contains no HTTP client, DNS, socket, redirect, TLS, proxy, or process primitive. | Source audit and adapter-only dependency boundary. |
| R10.5 controls | One `RunContext` owns atomic budget, concurrency, and rate controls. | Exhausted request-budget test blocks the next task before invocation. |
| Cancellation | Global and per-task contexts reach adapters; queued work becomes deterministic cancellation. | Pre-cancelled context and per-task-deadline tests. |
| Secret minimization | Context and result references are validated; events use bounded codes and `{}` metadata. | Secret-like target and adapter-reference rejection tests plus fuzzing. |
| Auditability | Project, assessment, task identity, status, timestamp, and bounded reason are emitted and persisted. | Event project-scope and R10.5 lifecycle persistence tests. |
| Finding separation | Result signals are not converted to findings. | Engine depends only on registry result identity/count/references. |

## Egress and secret audit

`internal/assessment` and `internal/assessmentexec` were audited for `net/http`, HTTP clients, direct requests, `net.Dial`, resolver calls, socket operations, `os/exec`, and command execution. No prohibited primitive is imported or called. URL parsing is validation-only and makes no network operation.

The engine returns generic boundary errors and bounded reason codes such as `adapter_failed`, `dependency_failed`, `budget_exhausted`, `authorization_expired`, and `cancelled`. It does not retain adapter error text in task results, events, CLI JSON, or SQLite metadata. Result evidence references are rejected when blank, oversized, or credential-like.

## Residual risk and intentional boundary

The engine cannot prove that a third-party caller’s adapter obeys R1/R3/R2/R10.5. Its boundary is to require the shared controls, preserve cancellation, validate scope/result identity, and make direct primitive use absent from the orchestration package. Owner adapters remain accountable for invoking the existing controlled transport and evidence paths.

The CLI’s built-in owners are deliberately fail-closed placeholders rather than reconstructed crawler, fuzzer, mutation, injection, validation, correlation, or reporting implementations. This leaves a partial persisted lifecycle rather than silently creating live traffic from insufficient task context. Wiring a real owner requires a separate, component-specific adapter change that preserves that owner’s documented R1/R3/R2 dependencies.

## Verification record

The R13.2 focused suite covers state transitions, topological dependency execution, malformed-plan rejection, profile and secret-context rejection, dry-run zero adapter dispatch, cancellation, per-task deadlines, shared budget exhaustion, authorization rechecks, project-scoped events, secret-bearing adapter result rejection, SQLite lifecycle persistence, and CLI dry-run/no-write behavior. The final branch verification additionally runs formatting, full Go tests, race tests, vet, build, frontend checks, whitespace checks, and a prohibited-primitive source audit.
